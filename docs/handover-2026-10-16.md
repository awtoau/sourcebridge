# Handover: evidence tooling and C# compiler recovery

**Date:** 2026-10-16

This is a sanitized engineering handover from a cross-pack work session. It
records durable decisions, measured results, and open work. It is not a raw
chat transcript and intentionally excludes machine-local paths, credentials,
and disposable build output.

The Sourcebridge coordination tracker is
[awtoau/sourcebridge#14](https://github.com/awtoau/sourcebridge/issues/14).

## Operating decisions

- Tooling and evidence come before broad conversion claims.
- Generated target code is a build artifact. Fix the converter, its rules, or
  the source facts; never hand-edit generated Rust.
- Compiling emitted code is not behavioral equivalence. Report compiler,
  source, target, and oracle evidence separately.
- Local Ollama may produce, validate, stage, or reject bounded proposals.
  It must not automatically promote a rule or write a generated artifact.
- The approved local model remains `qwen2.5-coder:14b`, pinned by digest and
  used through a loopback-only endpoint with fixed deterministic settings.
- Each language queue runs serially, is measured on a fixed evaluation set, and
  unloads the model before a language switch.

## Current C# work

The current error-elimination tracker is
[awtoau/csharp2rust#84](https://github.com/awtoau/csharp2rust/issues/84).
It owns nine remaining compiler diagnostics across seven modules.

The first class is C# composite-format logging:

```csharp
"RTC writing byte 0x{0:x} to register {1} (0x{1:x})", b, address
```

The existing literal formatter turns `{1:x}` into `{:x}` but discards the
argument index. The logging emitter consequently supplies `b, address` once
each for three Rust placeholders. The generic fix must parse literal C#
composite placeholders at the logging boundary and either expand/reorder the
arguments or emit valid Rust positional references. It must preserve compatible
`x`/`X` formats, omit source arguments proven unused by a no-placeholder
literal, and report unsupported C# formatting features explicitly.

Add focused tests for repeated indexes, multiple arguments, no-placeholder
messages with surplus source arguments, and unchanged interpolated-string
behavior. Then run the supported full compiler census and update the clean set
only through the supported recording mode. Commit the emitter change and the
ratchet data separately.

The historical overload-disambiguation regression remains separately tracked
by [awtoau/csharp2rust#78](https://github.com/awtoau/csharp2rust/issues/78).
Do not revive its old work in progress without a fresh isolated measurement.

## Next-agent workflow

1. Read the active issue before modifying code.
2. Use the repository's supported development entry point, not raw helper
   scripts as a separate workflow.
3. Inspect corpus facts before proposing a mapping. Reuse named corpus recipes
   rather than embedding ad hoc SQL in a worker.
4. Add the smallest focused regression test with each generic emitter change.
5. Run the smallest validation that proves the exact change, then the full
   compiler census when emitted output changes.
6. Treat generated output, local model output, and broad emission counts as
   evidence inputs, not correctness claims.
7. Commit small coherent changes, push them, and preserve unrelated work in a
   dirty worktree.
